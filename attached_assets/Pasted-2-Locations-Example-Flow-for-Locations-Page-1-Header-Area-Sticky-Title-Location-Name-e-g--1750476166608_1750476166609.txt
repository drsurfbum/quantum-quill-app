2. Locations

Example Flow for Locations Page
	1.	Header Area (Sticky)
	•	Title: Location Name (e.g., “Phobos Base Alpha”)
	•	Badges: Type (Planet/Moon/City/Station/Structure), Status (Inhabited/Abandoned)
	•	Save/Delete icons.
	2.	Main Column
	•	Core Info (expanded initially):
	•	Name
	•	Type dropdown
	•	Parent Location (link selector)
	•	Short Notes / Tagline (one-liner)
	•	Physical & Environmental Details (collapsible):
	•	Environment/Biome (e.g., Desert, Ice, Urban)
	•	Coordinates or Map Reference (if applicable)
	•	Basic metrics: size, gravity, atmosphere (for planets) or capacity/layout (for structures)
	•	Significance & Function (collapsible):
	•	Purpose (military base, trading hub, hidden temple, spaceship hangar)
	•	Key features or facilities
	•	History & Timeline (collapsible):
	•	Founding or creation date/era
	•	Major events tied here (link to Event entries)
	•	Status changes (e.g., destroyed, terraformed)
	•	Inhabitants & Governance (collapsible):
	•	Linked Groups/Races that control or inhabit
	•	Notable Characters associated (link roles: Governor, Resident)
	•	Relational Connections (collapsible):
	•	Nearby or connected Locations
	•	Linked World Elements present (e.g., unique flora/fauna, technology)
	•	Notes / Development Ideas (collapsed by default):
	•	Future expansion, plot hooks, lore puzzles.
	3.	Sidebar
	•	Classification:
	•	Type, Status
	•	Tags/Significance:
	•	e.g., “Mining Colony,” “Capital,” “Secret Outpost”
	•	Links:
	•	Related Events summary (recent)
	•	Related Characters/Groups (chips)
	•	Timestamps & Actions:
	•	Created/Updated
	•	Archive toggle
	4.	Post-Save Suggestions
	•	“Would you like to create an Event for its founding?” or “Link to existing Events here.”
	•	“View other Locations on the same parent (e.g., other moons of Mars).”

Prioritization (≤150 words)

Locations shape geography and narrative staging, serving as the stage where Events occur and Characters interact. Start by capturing name, type, parent location, and a concise purpose summary. Early linking to controlling Groups/Races and key Events prevents isolated entries. Basic environmental tags (biome/status) allow filtering. Postpone detailed environmental stats until you have multiple entries to compare (e.g., all desert planets). Emphasize relational linking: ensure each Location can show “who inhabits this” and “what happened here.” A well-structured Location template streamlines scene planning and world navigation. Collapsing less critical fields keeps the entry approachable, expanding details later as the world deepens.
