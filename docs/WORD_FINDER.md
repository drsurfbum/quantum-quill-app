# Word Finder — QQ-32

English dictionary and thesaurus inside Write. Open the book icon beside the Story
Bible link tool with a word selected, or type a query. Results group definitions,
synonyms and antonyms by meaning; examples and related concepts expand on demand.
Related concepts open another lookup. Choosing a synonym/antonym only previews it;
**Replace selection** is the explicit edit. Undo and Redo are visible beside Version history in the combined Write toolbar.

## Data and privacy

The pinned Open English WordNet **2025** edition (common nouns, verbs, adjectives
and adverbs; not the separate Namenet/proper-name supplement) is distributed with
the app. No runtime dictionary provider, API key, new npm package, database table,
server query endpoint, or hosting service is introduced. This does not make the
whole app available offline.

- Source: <https://en-word.net/static/english-wordnet-2025.xml.gz>
- Project: <https://github.com/globalwordnet/english-wordnet/tree/2025-edition>
- Input SHA-256: `9ca6d1dcb75f822fdd66617f7d9da48142ace38dd544d6ad5e2feca1674ad3fe`
- 135,969 lexical entries, 107,519 synsets, 131,094 normalized lookup keys.
- 256 gzip shards, 16,684,897 compressed bytes in total. The largest decoded shard
  is 312,384 bytes. Only requested shards load; the browser retains at most eight.
- Query normalization, bucket selection and exact lookup happen in the browser.
  Requests contain only a two-digit bucket identifier, with no query text,
  surrounding prose, account/project identifier, cookies or referrer. The app's
  ordinary static access logs may contain those bucket paths. Buckets are not an
  encryption or anonymity mechanism.
- No lookup history, localStorage query persistence, analytics or provider calls.
  A request occurs only on opening a valid selected word or submitting a query,
  not on every keystroke. Closing/changing queries cancels stale results.
- Modern browser `DecompressionStream` support is required. Unsupported browsers
  show a clear lookup error without affecting writing. Physical iPad and software
  keyboard behavior still require device acceptance; WebKit emulation is not that.

## License and reproducibility

The data is **CC BY 4.0**, with retained Princeton WordNet attribution and its
underlying license notice. Credit goes to the Open English WordNet team and
Princeton University WordNet. Copies of both upstream notices are distributed in
`client/public/wordnet/2025-v1/` and linked in the widget. These data terms are
separate from the app's MIT code license. We reuse data, not an upstream widget or
software wrapper. Source texts remain verbatim; QQ normalizes lookup keys, combines
provided word forms, groups senses, and flattens selected lexical relations into
labels. No definitions or examples are generated by AI. Not every sense supplies
antonyms or examples. Words in one sense are not necessarily interchangeable in
every sentence; the writer chooses the intended meaning, casing and inflection.

Rebuild with Python's standard library, using the downloaded pinned source:

```sh
python3 scripts/build-wordnet.py /path/to/english-wordnet-2025.xml.gz
```

The script performs no network access and refuses a different input hash. Gzip
timestamps are zero; the manifest records each output's compressed hash and size.
Production builds copy these vendored public files without a network download.
Review and version a future data update rather than replacing a live path silently.

## Writing safeguards

- Lookup alone creates no editor transaction or save. Dismissal restores focus
  without scrolling when the original editor selection remains current.
- Replacement uses one ordinary editor transaction and existing autosave/recovery/
  revision/conflict protections. History boundaries isolate it from preceding and
  subsequent typing. One Undo restores the original text and formatting; Redo
  reapplies it. This is in-session undo history. Changed saves also enter the separate saved-version history; restoring a saved version starts a new undo session.
- Captured targets require the same editor document and selection. Any intervening
  document edit or selection change invalidates replacement. Switching a project,
  chapter or scene remounts the tool and discards its target and pending query.
- Replacement accepts only a single textblock with consistent marks. Story Bible
  references, hyperlinks, mixed formatting and inline atoms remain lookup-only.
  This avoids guessing how to redistribute semantic links or formatting.
- Replacement inserts literal text nodes, never HTML from lexical data.
- The panel does not resize the prose surface. It scrolls internally, and moves
  toward the viewport top in short windows to keep its controls reachable.

## Verification and delivery boundary

Validation uses the disposable, loopback-only `tests/showcase-server.ts`, with
fictional writing in memory. No actual user accounts, manuscript database or
production service are involved.

- Node 24 typecheck and production build.
- 474 tests / 46 suites: includes shard hashes/key placement, real data coverage,
  literal text insertion, formatting, stale selection, read-only protection and
  separated undo/redo boundaries, plus existing save/conflict/isolation checks.
- `tests/word-finder-browser.mjs`: actual Chromium and WebKit at desktop, tablet
  and narrow widths; explicit replacement, Undo/Redo, save/reload, typed lookup,
  unknown words, stale edit rejection, keyboard focus, dark/short layouts and
  bucket-only requests. Environment variables select an existing Playwright
  installation and a disposable fixture port; no lockfile change is needed.

This feature is for draft-PR review. No merge or deployment is included. QQ-31
owns changes to visible history/Undo/Redo placement; QQ PM owns the shared roadmap.
Rhyme, phonetics, phrase generation, context-aware ranking and persistent versions
are outside this slice. The extra static payload may affect transfer/storage costs;
no additional paid service or hosting-plan change has been made.
